اتصال دیتابیس و APIهای دریافت و ساخت کاربر طبق آزمایش‌هایی که انجام دادی، درست کار کردند.

نتیجه نهایی تست PATCH هنوز مشخص نشده است. API حذف کاربر هم هنوز پیاده‌سازی نشده است.

۲. ساختار جدول users

Entity کاربر در مسیر زیر قرار دارد:

src/modules/users/entities/user.entity.ts

ستون کاربرد
id شناسه یکتای کاربر
name نام کاربر با حداکثر ۱۰۰ کاراکتر
email ایمیل کاربر با محدودیت یکتا بودن
createdAt زمان ایجاد رکورد
updatedAt زمان آخرین ویرایش رکورد

چرا email یکتا است؟

چون در Entity از unique استفاده شده است، دیتابیس اجازه نمی‌دهد دو کاربر ایمیل یکسان داشته باشند.

۳. تنظیمات اتصال دیتابیس

فایل: src/database/data-source.ts 

import "reflect-metadata";
import { DataSource } from "typeorm";
import { env } from "../config/env";
import { User } from "../modules/users/entities/user.entity";

export const AppDataSource = new DataSource({
  type: "mysql",
  host: env.DB_HOST,
  port: env.DB_PORT,
  username: env.DB_USERNAME,
  password: env.DB_PASSWORD,
  database: env.DB_DATABASE,
  entities: [User],
  migrations: ["articles-backend/src/database/migrations/*.ts"],
  synchronize: false,
  logging: false,
});

نکات فنی

  • DataSource تنظیمات اتصال و دسترسی TypeORM به دیتابیس را فراهم می‌کند.
  • type: "mysql" برای اتصال TypeORM به MariaDB نیز استفاده می‌شود.
  • پکیج mysql2 درایور ارتباط برنامه با دیتابیس است.
  • entities: [User] به TypeORM معرفی می‌کند که Entity کاربر را بشناسد.
  • synchronize: false از تغییر خودکار ساختار دیتابیس براساس Entity جلوگیری می‌کند.
  • Migrationها برای مدیریت تغییرات ساختار دیتابیس استفاده می‌شوند.

۴. مفهوم DTO و Zod

DTO چیست؟

DTO مخفف Data Transfer Object است. این مفهوم مشخص می‌کند چه ساختاری از داده را بین بخش‌های برنامه منتقل می‌کنیم.

Zod چیست؟

Zod یک کتابخانه اعتبارسنجی است که داده‌های ورودی را در زمان اجرا بررسی می‌کند.

فایل: src/modules/users/users.dto.ts 

import { z } from "zod";

export const createUserSchema = z.object({
  name: z.string().trim().min(2).max(100),
  email: z.string().trim().email().max(150),
});

export type CreateUserDto =
  z.infer<typeof createUserSchema>;

export const updateUserSchema =
  createUserSchema.partial();

export type UpdateUserDto =
  z.infer<typeof updateUserSchema>;

توضیح بخش‌های مهم

  • z.object(): ساختار شیء ورودی را تعریف می‌کند.
  • z.string(): مشخص می‌کند مقدار باید رشته باشد.
  • trim(): فاصله ابتدا و انتهای رشته را حذف می‌کند.
  • min(2): حداقل طول نام را مشخص می‌کند.
  • max(100): حداکثر طول نام را مشخص می‌کند.
  • email(): قالب ایمیل را بررسی می‌کند.
  • z.infer: نوع TypeScript را از Schema استخراج می‌کند.
  • partial(): همه فیلدها را برای ویرایش اختیاری می‌کند.

DTO و Schema یک چیز نیستند: Schema قوانین اعتبارسنجی زمان اجرا را تعریف می‌کند؛ نوع DTO به TypeScript کمک می‌کند نوع داده‌ها را در زمان توسعه بررسی کند.

۵. کنترلر کاربران

کنترلر درخواست را دریافت می‌کند، منطق لازم را اجرا می‌کند و پاسخ مناسب را به مشتری برمی‌گرداند.

دریافت Repository

const userRepository =
  AppDataSource.getRepository(User);

Repository ابزار TypeORM برای کار با Entity متناظر با جدول دیتابیس است.

دریافت همه کاربران

const users = await userRepository.find();

res.json({
  success: true,
  data: users,
});

متد find() رکوردهای جدول را دریافت می‌کند. اگر جدول خالی باشد، نتیجه معمولاً آرایه خالی است: []. این نتیجه به‌خودی‌خود خطا نیست.

ساخت کاربر

const result = createUserSchema.safeParse(req.body);

if (!result.success) {
  return res.status(400).json({
    success: false,
    message: "اطلاعات ورودی معتبر نیست",
  });
}

const user = userRepository.create(result.data);
const savedUser = await userRepository.save(user);

return res.status(201).json({
  success: true,
  data: savedUser,
});
  • req.body اطلاعات ارسال‌شده در بدنه درخواست است.
  • safeParse() ورودی را اعتبارسنجی می‌کند.
  • create() یک Entity می‌سازد؛ اما به‌تنهایی آن را در دیتابیس ذخیره نمی‌کند.
  • save() عملیات ذخیره را انجام می‌دهد.
  • 201 Created پاسخ متداول برای ایجاد موفق است.

دریافت کاربر با شناسه

const id = Number(req.params.id);

const user = await userRepository.findOneBy({ id });

مقدار req.params.id در ابتدا رشته است؛ بنابراین آن را به عدد تبدیل و اعتبارسنجی می‌کنیم.

اگر کاربر پیدا نشود، پاسخ مناسب 404 Not Found است.

ویرایش کاربر

userRepository.merge(user, result.data);

const updatedUser =
  await userRepository.save(user);

merge() داده‌های جدید را با Entity موجود ادغام می‌کند و save() تغییرات را ذخیره می‌کند. در PATCH می‌توان فقط فیلدهایی را که می‌خواهیم تغییر کنند فرستاد.

۶. Route چیست؟

Route مشخص می‌کند درخواست با چه متد HTTP و چه آدرسی به کدام کنترلر برسد.

فایل: src/routes/index.ts 

apiRouter.get("/users", getUsers);
apiRouter.post("/users", createUser);
apiRouter.get("/users/:id", getUserById);
apiRouter.patch("/users/:id", updateUser);

چون Router با پیشوند /api/v1 ثبت شده، آدرس /users به /api/v1/users تبدیل می‌شود.

تفاوت Route و Controller

  • Route مسیر رسیدن درخواست به تابع را مشخص می‌کند.
  • Controller منطق مربوط به درخواست را اجرا می‌کند.

Middleware مربوط به JSON

app.use(express.json());

این Middleware باید پیش از Routeهای API ثبت شده باشد تا JSON درخواست در req.body در دسترس قرار بگیرد.

۷. APIهای فعلی پروژه

متد مسیر کاربرد
GET /api/v1/users دریافت همه کاربران
POST /api/v1/users ساخت کاربر
GET /api/v1/users/:id دریافت یک کاربر
PATCH /api/v1/users/:id ویرایش کاربر
DELETE /api/v1/users/:id هنوز ساخته نشده است

۹. کدهای وضعیت HTTP

کد معنی
200 درخواست موفق
201 منبع جدید ساخته شد
400 ورودی نامعتبر است
404 منبع موردنظر پیدا نشد
500 خطای داخلی سرور

خطاهایی مانند ایمیل تکراری باید با Error Middleware مدیریت شوند. بهتر است جزئیات داخلی دیتابیس در پاسخ عمومی API افشا نشود.

  1. بررسی نتیجه تست PATCH.
  2. ساخت API حذف کاربر با DELETE.
  3. مدیریت استاندارد خطاهای دیتابیس.
  4. طراحی Entity مقاله و رابطه آن با نویسنده.
