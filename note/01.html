جزوه آموزشی امروز: ساخت بک‌اند سایت مقاله

مرور مرحله‌به‌مرحله پروژه، ساختار پوشه‌ها، تنظیمات، اتصال دیتابیس، Migration و وضعیت ادامه کار

وضعیت امروز: اتصال برنامه به MariaDB تأیید شد، مسیرهای اولیه API تست شدند و Migration جدول users با موفقیت اجرا شد.
نکته مهم: مسیر آزمایشی GET /api/v1/users پیشنهاد شده، اما هنوز تأیید نشده که تغییر آن را در فایل انجام داده‌ای.

۱. هدف پروژه

در حال ساخت بک‌اند یک سایت مقاله و پنل مدیریت هستیم. فناوری‌های فعلی:

  • TypeScript: زبان برنامه‌نویسی با بررسی نوع داده‌ها.
  • Express.js: دریافت درخواست‌های HTTP و تعریف مسیرهای API.
  • TypeORM: ارتباط بین کلاس‌های TypeScript و جداول دیتابیس.
  • MariaDB از طریق XAMPP: محل ذخیره‌سازی اطلاعات.
  • REST API: راهی استاندارد برای ارتباط فرانت‌اند با بک‌اند.
  • Migration: ثبت کنترل‌شده تغییرات ساختار دیتابیس.

پیشوند API پروژه /api/v1 است؛ یعنی مسیرهای نسخه اول API با این بخش شروع می‌شوند.

۵. متغیرهای محیطی در .env

فایل .env در ریشه پروژه قرار دارد، نه داخل پوشه articles-backend.

  • PORT: پورتی که Express روی آن گوش می‌دهد.
  • DB_HOST و DB_PORT: آدرس و پورت MariaDB.
  • DB_USERNAME و DB_PASSWORD: مشخصات ورود به دیتابیس.

۶. خواندن و اعتبارسنجی متغیرهای محیطی

محتوای اصلی articles-backend/src/config/env.ts:

import "dotenv/config";

function getEnv(key: string, fallback?: string): string {
  const value = process.env[key] ?? fallback;

  if (value === undefined || value.trim() === "") {
    throw new Error(`Missing required environment variable: ${key}`);
  }

  return value;
}

function getNumberEnv(key: string, fallback: number): number {
  const value = Number(getEnv(key, String(fallback)));

  if (!Number.isInteger(value) || value <= 0) {
    throw new Error(
      `Environment variable ${key} must be a positive integer`
    );
  }

  return value;
}

export const env = {
  NODE_ENV: getEnv("NODE_ENV", "development"),
  PORT: getNumberEnv("PORT", 3000),

  DB_HOST: getEnv("DB_HOST", "localhost"),
  DB_PORT: getNumberEnv("DB_PORT", 3306),
  DB_USERNAME: getEnv("DB_USERNAME"),
  DB_PASSWORD: process.env.DB_PASSWORD ?? "",
  DB_DATABASE: getEnv("DB_DATABASE"),
};

این کد فایل محیطی را بارگذاری می‌کند، مقادیر ضروری را بررسی می‌کند و پورت‌ها را به عدد مثبت تبدیل می‌کند. رمز دیتابیس می‌تواند رشته خالی باشد.

import "reflect-metadata";

چرا type: "mysql"؟ در این پروژه از درایور mysql2 استفاده می‌کنیم که با MariaDB در XAMPP سازگار است.

۸. موجودیت User

فایل articles-backend/src/modules/users/entities/user.entity.ts کلاس TypeScript متناظر با جدول users است.

import {
  Entity,
  PrimaryGeneratedColumn,
  Column,
  CreateDateColumn,
  UpdateDateColumn,
} from "typeorm";

@Entity({ name: "users" })
export class User {
  @PrimaryGeneratedColumn()
  id!: number;

  @Column({ type: "varchar", length: 100 })
  name!: string;

  @Column({ type: "varchar", length: 150, unique: true })
  email!: string;

  @CreateDateColumn()
  createdAt!: Date;

  @UpdateDateColumn()
  updatedAt!: Date;
}
ستونمعنی
idشناسه اصلی و افزایشی هر کاربر.
nameنام کاربر؛ حداکثر ۱۰۰ کاراکتر.
emailایمیل؛ حداکثر ۱۵۰ کاراکتر و یکتا.
createdAtزمان ساخته‌شدن رکورد که TypeORM مدیریت می‌کند.
updatedAtزمان آخرین تغییر رکورد که TypeORM مدیریت می‌کند.

وقتی می‌گوییم email یکتا است، یعنی دیتابیس اجازه نمی‌دهد دو کاربر ایمیل یکسان داشته باشند.

۹. ساختار Express و مسیرهای API

server.ts

import "reflect-metadata";
import app from "./app";
import { env } from "./config/env";
import { AppDataSource } from "./database/data-source";

async function bootstrap() {
  try {
    await AppDataSource.initialize();

    console.log("Database connected successfully ✅");

    app.listen(env.PORT, () => {
      console.log(
        `Server is running on http://localhost:${env.PORT}`,
      );
    });
  } catch (error) {
    console.error("Failed to start server:", error);
    process.exit(1);
  }
}

bootstrap();

ترتیب مهم است: ابتدا اتصال دیتابیس برقرار می‌شود؛ سپس سرور HTTP اجرا می‌شود. اگر اتصال دیتابیس شکست بخورد، برنامه با خطا متوقف می‌شود.

app.ts

import express from "express";
import cors from "cors";
import helmet from "helmet";
import { appConfig } from "./config/app.config";
import { apiRouter } from "./routes";
import { errorMiddleware } from "./common/middleware/error.middleware";
import { notFoundMiddleware } from "./common/middleware/not-found.middleware";

const app = express();

app.use(helmet());
app.use(cors());
app.use(express.json());

app.get("/", (_req, res) => {
  res.send(`${appConfig.name} API is running 🚀`);
});

app.use(appConfig.apiPrefix, apiRouter);

app.use(notFoundMiddleware);
app.use(errorMiddleware);

export default app;

helmet() تعدادی هدر امنیتی HTTP را تنظیم می‌کند؛ cors() تنظیمات اشتراک درخواست بین مبدأها را اعمال می‌کند؛ express.json() بدنه JSON درخواست‌ها را می‌خواند.

routes/index.ts — وضعیت فعلی تأییدنشده

کد قبلی مسیر پایه API این بود:

import { Router } from "express";

export const apiRouter = Router();

apiRouter.get("/", (_req, res) => {
  res.json({
    success: true,
    message: "Articles API is running 🚀",
  });
});

در پایان جلسه پیشنهاد شد مسیر آزمایشی زیر هم به همین فایل اضافه شود؛ هنوز تأیید نشده که این تغییر انجام شده باشد:

apiRouter.get("/users", (_req, res) => {
  res.json({
    success: true,
    message: "Users API is running 🚀",
  });
});

با توجه به ثبت router زیر پیشوند /api/v1، آدرس این مسیر GET /api/v1/users خواهد بود. فعلاً پاسخ آزمایشی است و از دیتابیس اطلاعاتی نمی‌خواند.

۱۰. مدیریت خطاها

app.error.ts

export class AppError extends Error {
  constructor(
    message: string,
    public readonly statusCode: number = 500,
  ) {
    super(message);

    this.name = "AppError";
    Object.setPrototypeOf(this, new.target.prototype);
  }
}

AppError خطایی سفارشی است که همراه پیام، کد وضعیت HTTP را نگه می‌دارد.

not-found.middleware.ts

import type { RequestHandler } from "express";
import { AppError } from "../errors/app.error";

export const notFoundMiddleware: RequestHandler = (
  _req,
  _res,
  next,
) => {
  next(new AppError("مسیر موردنظر پیدا نشد", 404));
};

error.middleware.ts

import type { ErrorRequestHandler } from "express";
import { AppError } from "../errors/app.error";

export const errorMiddleware: ErrorRequestHandler = (
  err,
  _req,
  res,
  _next,
) => {
  if (err instanceof AppError) {
    res.status(err.statusCode).json({
      success: false,
      message: err.message,
    });
    return;
  }

  console.error(err);

  res.status(500).json({
    success: false,
    message: "خطای داخلی سرور",
  });
};

ترتیب middlewareها مهم است: ابتدا مسیرهای برنامه، سپس middleware مسیر پیدا نشد، و در آخر middleware مدیریت خطا ثبت شده‌اند.

۱۱. Migration چیست و چه اتفاقی افتاد؟

Migration فایلی است که تغییر ساختار دیتابیس را به‌شکل نسخه‌بندی‌شده ثبت می‌کند. به‌جای تغییر خودکار دیتابیس، تغییرها را صریح و قابل پیگیری اجرا می‌کنیم.

فرمان تولید Migration

npx tsx ./node_modules/typeorm/cli.js migration:generate articles-backend/src/database/migrations/CreateUsersTable -d articles-backend/src/database/data-source.ts

فایل زیر با موفقیت تولید شد:

articles-backend/src/database/migrations/1791791848214-CreateUsersTable.ts

خلاصه SQL ساخته‌شده

CREATE TABLE `users` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(100) NOT NULL,
  `email` varchar(150) NOT NULL,
  `createdAt` datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  `updatedAt` datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
    ON UPDATE CURRENT_TIMESTAMP(6),
  UNIQUE INDEX `IDX_97672ac88f789774dd47f7c8be` (`email`),
  PRIMARY KEY (`id`)
) ENGINE=InnoDB

متد up() تغییر را اعمال می‌کند و متد down() برای برگرداندن تغییر نوشته می‌شود. قبل از اجرای Migration باید محتوای آن بررسی شود.

۱۲. خطای CLI و راه‌حلی که استفاده شد

فرمان معمول npx typeorm migration:show -d ... خطای زیر داد:

Cannot use import statement outside a module

علت این بود که CLI فایل TypeScript را با روش بارگذاری فعلی پروژه درست باز نمی‌کرد. سپس typeorm-ts-node-commonjs امتحان شد، اما چون ts-node نصب نبود، خطای Cannot find module 'ts-node' رخ داد.

در نهایت اجرای CLI با tsx استفاده شد:

npx tsx ./node_modules/typeorm/cli.js migration:show -d articles-backend/src/database/data-source.ts

این دستور بدون خروجی و با کد خروجی صفر تمام شد. سپس فرمان migration:generate و فرمان migration:run با همین روش موفق شدند.

برای اجرای فرمان‌های Migration در آینده از همان روش موفق استفاده کن، اما قبل از هر Migration تغییردهنده، فایل تولیدشده را بازبینی کن. همچنین مسیرهای فایل و تنظیمات TypeORM را در صورت تغییر محیط دوباره بررسی کن.
