TypeScript | Express | TypeORM | MariaDB | REST API

۱. کارهایی که انجام دادیم

  • ساخت جدول کاربران با Migration
  • ساخت جدول مقالات و ارتباط آن با کاربران
  • ساخت APIهای CRUD کاربران
  • ساخت APIهای CRUD مقاله‌ها
  • اعتبارسنجی ورودی‌ها با Zod
  • مدیریت خطا با AppError و Error Middleware
  • جلوگیری از ثبت slug تکراری
  • صفحه‌بندی مقاله‌ها (Pagination)
  • فیلتر مقاله‌ها بر اساس وضعیت
  • جست‌وجو بر اساس عنوان مقاله
هدف معماری این است که مسیرها، کنترلرها، سرویس‌ها و دسترسی به دیتابیس از هم جدا باشند.

وظیفه هر بخش

  • Route: تعیین می‌کند هر درخواست به کدام کنترلر برود.
  • Controller: ورودی HTTP را می‌خواند و پاسخ را برمی‌گرداند.
  • Service: منطق اصلی برنامه را اجرا می‌کند.
  • Repository: عملیات خواندن و نوشتن در دیتابیس را انجام می‌دهد.
  • Entity: ساختار یک جدول و ارتباطات آن را تعریف می‌کند.
  • Migration: تغییرات ساختار دیتابیس را مدیریت می‌کند.
  • DTO: شکل داده‌ای را که بین بخش‌های برنامه منتقل می‌شود مشخص می‌کند.
  • Zod: اعتبار ورودی واقعی را در زمان اجرا بررسی می‌کند.

ستون articles.userId به ستون users.id اشاره می‌کند.

  • Primary Key: شناسه یکتای هر ردیف.
  • Foreign Key: اتصال رکورد به رکورد معتبر در جدول دیگر.
  • ManyToOne: چند مقاله می‌توانند یک نویسنده داشته باشند.
  • JoinColumn: مشخص می‌کند ستون ارتباطی در دیتابیس کدام است.
اگر خطای ER_NO_REFERENCED_ROW_2 دیدی، ممکن است userId فرستاده‌شده در جدول users وجود نداشته باشد.

۴. راهنمای APIهای کاربران

آدرس پایه:

http://localhost:3000/api/v1
متد آدرس کاربرد
GET /users دریافت همه کاربران
POST /users ساخت کاربر جدید
GET /users/:id دریافت یک کاربر با شناسه
PATCH /users/:id ویرایش بخشی از کاربر
DELETE /users/:id حذف کاربر

مثال: ویرایش کاربر

PATCH http://localhost:3000/api/v1/users/1

{
  "name": "Ali Reza"
}

چون از PATCH استفاده می‌کنیم، لازم نیست همه فیلدهای کاربر را ارسال کنیم.

۵. راهنمای APIهای مقاله‌ها

متد آدرس کاربرد
POST /articles ساخت مقاله
GET /articles دریافت فهرست مقاله‌ها
GET /articles/:id دریافت یک مقاله
PATCH /articles/:id ویرایش مقاله
DELETE /articles/:id حذف مقاله

ساخت مقاله

در Postman بخش Body → raw → JSON را انتخاب کن.

POST http://localhost:3000/api/v1/articles

{
  "title": "آموزش TypeScript",
  "slug": "learn-typescript",
  "content": "این اولین مقاله ماست.",
  "status": "draft",
  "userId": 1
}
  • title: عنوان مقاله.
  • slug: شناسه متنی مناسب URL که باید یکتا باشد.
  • content: محتوای مقاله.
  • status: وضعیت مقاله؛ draft یا published.
  • userId: شناسه نویسنده موجود در جدول کاربران.

دریافت همه مقاله‌ها

GET http://localhost:3000/api/v1/articles

دریافت یک مقاله

GET http://localhost:3000/api/v1/articles/1

ویرایش مقاله

PATCH http://localhost:3000/api/v1/articles/1

{
  "title": "آموزش پیشرفته TypeScript"
}

حذف مقاله

DELETE http://localhost:3000/api/v1/articles/1
درخواست DELETE اطلاعات را واقعاً حذف می‌کند. برای آزمایش، مقاله‌ای را انتخاب کن که به آن نیاز نداری.

۶. صفحه‌بندی (Pagination)

وقتی تعداد مقاله‌ها زیاد باشد، بهتر است همه را در یک درخواست برنگردانیم. صفحه‌بندی تعداد نتایج هر درخواست را محدود می‌کند. 

GET /api/v1/articles?page=1&limit=5
  • page: شماره صفحه.
  • limit: تعداد مقاله‌ها در هر صفحه.
  • skip: تعداد ردیف‌هایی که از آن‌ها عبور می‌کنیم.
  • take: تعداد ردیف‌هایی که می‌خواهیم دریافت کنیم.
  • total: تعداد کل رکوردهای مطابق فیلتر.
  • totalPages: تعداد کل صفحات.
skip = (page - 1) * limit

مثلاً برای صفحه ۳ و limit برابر ۱۰:

skip = (3 - 1) * 10
skip = 20

یعنی ۲۰ رکورد اول نادیده گرفته می‌شوند و حداکثر ۱۰ رکورد بعدی برمی‌گردند.

۷. فیلتر مقاله‌ها بر اساس وضعیت

فقط مقاله‌های منتشرشده

GET /api/v1/articles?status=published

فقط پیش‌نویس‌ها

GET /api/v1/articles?status=draft

مقدار status باید یکی از دو مقدار مجاز باشد. اگر مقدار نامعتبر ارسال شود، API باید خطای 400 برگرداند.

فیلتر وضعیت، مجوز دسترسی نیست. تا زمانی که احراز هویت و بررسی مجوز انجام نشده، نباید پیش‌نویس‌های خصوصی را در اختیار کاربران عمومی قرار دهیم.

۸. جست‌وجوی مقاله بر اساس عنوان

جست‌وجوی TypeScript

GET /api/v1/articles?search=TypeScript

ترکیب جست‌وجو، فیلتر و صفحه‌بندی

GET /api/v1/articles?page=1&limit=5&status=published&search=TypeScript

سرویس با Query Builder شرط جست‌وجو را اضافه می‌کند. مقدار جست‌وجو باید به شکل پارامتر bind شود، نه با چسباندن مستقیم ورودی کاربر به SQL. 

if (search?.trim()) {
  query.andWhere("article.title LIKE :search", {
    search: `%${search.trim()}%`,
  });
}
مزیت Query Builder این است که می‌توانیم شرط‌های مختلف را به‌صورت مرحله‌ای بسازیم؛ مثلاً وضعیت، عنوان و صفحه‌بندی را با هم ترکیب کنیم.

۹. نکات کلیدی TypeScript و Express

DTO

DTO شکل داده‌ای را مشخص می‌کند که یک عملیات انتظار دارد. 

export interface CreateArticleDto {
  title: string;
  slug: string;
  content: string;
  status?: "draft" | "published";
  userId: number;
}

اختیاری بودن فیلد

علامت ? یعنی فرستادن آن فیلد اجباری نیست. 

status?: "draft" | "published";

اعتبارسنجی با Zod

TypeScript هنگام کامپایل به بررسی نوع‌ها کمک می‌کند؛ اما JSON دریافتی از اینترنت باید در زمان اجرا هم اعتبارسنجی شود. 

export const updateArticleSchema = z.object({
  title: z.string().trim().min(3).max(200).optional(),
  slug: z.string().trim().min(3).max(250).optional(),
  content: z.string().min(1).optional(),
  status: z.enum(["draft", "published"]).optional(),
});

مدیریت خطا

try {
  const article = await getArticleById(id);

  res.status(200).json({
    success: true,
    data: article,
  });
} catch (error) {
  next(error);
}

با next(error) خطا به Error Middleware ارسال می‌شود تا پاسخ خطا به‌صورت متمرکز مدیریت شود.

۱۰. کدهای مهم HTTP

کد معنی
200 درخواست موفق و پاسخ دارای محتوا.
201 منبع جدید ساخته شده است.
204 عملیات موفق است و بدنه پاسخ ندارد.
400 ورودی نامعتبر است.
404 منبع موردنظر پیدا نشده است.
409 تعارض؛ مانند ایمیل یا slug تکراری.
500 خطای غیرمنتظره سمت سرور.

۱۱. خطاهایی که امروز بررسی کردیم

خطای Foreign Key

ER_NO_REFERENCED_ROW_2
Cannot add or update a child row

دلیل: مقاله به کاربری اشاره می‌کند که شناسه‌اش در جدول users وجود ندارد. ابتدا این درخواست را بزن: 

GET http://localhost:3000/api/v1/users

ایمیل تکراری

اگر ایمیل در دیتابیس یکتا باشد و دوباره استفاده شود، دیتابیس خطای ER_DUP_ENTRY می‌دهد. این خطا باید به پاسخ مناسب مانند 409 تبدیل شود.

شناسه نامعتبر

قبل از جست‌وجوی رکورد، بررسی می‌کنیم شناسه عدد صحیح مثبت باشد. 

const id = Number(req.params.id);

if (!Number.isInteger(id) || id < 1) {
  throw new AppError("شناسه معتبر نیست", 400);
}

۱۲. نکات امنیتی مهم

وضعیت فعلی: احراز هویت و بررسی مالکیت مقاله‌ها هنوز کامل نشده است. APIهای تغییر و حذف را فعلاً عمومی نکن.
  • هنگام ساخت مقاله، در نسخه نهایی userId باید از هویت کاربر احراز هویت‌شده گرفته شود.
  • قبل از ویرایش یا حذف مقاله، مجوز کاربر برای همان مقاله بررسی شود.
  • پیش‌نویس‌ها نباید بدون مجوز در اختیار کاربران عمومی قرار بگیرند.
  • ورودی‌ها باید با Zod اعتبارسنجی شوند.
  • برای جست‌وجوی دیتابیس از پارامترهای امن استفاده شود.
  • جزئیات داخلی SQL و خطاهای حساس به کاربر عمومی نمایش داده نشوند.
  • برای محیط واقعی، محدودیت نرخ درخواست و مدیریت امن تنظیمات محرمانه را در نظر بگیر.
  • قبل از اجرای Migration روی دیتابیس مهم، تنظیمات اتصال را بررسی کن.

  4. بررسی خروجی‌ها و رفع خطاهای احتمالی.
  5. پیاده‌سازی احراز هویت و بررسی مالکیت مقاله‌ها.
